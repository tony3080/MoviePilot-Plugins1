# RSS一条龙：ReelHarbor V1 功能迁移为 MoviePilot 插件的实现提示词

## 角色与目标

你是一名熟悉 MoviePilot 插件体系、qBittorrent、PT RSS、媒体识别、硬链接入库、Emby 和 CloudDrive2 的产品工程师。

请把 ReelHarbor V1 的以下功能重做成 MoviePilot 插件“RSS一条龙”：

1. 入库管理
2. QB 管理
3. VT+
4. 系统设置中的 CD2 设置及其待入库联动

本文描述的是业务逻辑和用户可观察行为，不要求照搬 V1 的代码、数据库、接口或页面结构。MoviePilot 已有的认证、用户权限、插件配置存储、数据库、任务调度、下载器管理、媒体识别、站点信息、通知、事件系统、文件系统适配和前端组件必须优先复用，不要重复建设基础设施。

插件身份固定如下：展示名称为 `RSS一条龙`，Python 主类、插件 ID、前端联邦名称和 `package.v2.json` 键均为 `RssAllInOne`，目录为 `plugins.v2/rssallinone`，配置前缀为 `rssallinone_`。

本文中的“入库”不是 MoviePilot 的媒体整理或转移入库。它专指：根据 MoviePilot 识别和命名结果，在同盘 staging 目录创建硬链接，交由 CloudDrive2 备份到云端目标，并在云端目录重新挂载后供 MoviePilot/Emby 库存检查和扫库使用。插件不得把该流程伪装为 MoviePilot 原生转移任务。

### 当前命名边界（覆盖旧版 qB 重命名描述）

- 插件不得重命名 qB 下载目录中的文件或目录，qB 源路径和源文件名保持不变。
- MoviePilot 命名模板、自定义识别词、重命名规则、中文标题、国配和特效标记，只用于生成硬链接目标的 `new_rel`、`local_hardlink_path` 和库存预期路径。
- 源文件名与硬链接文件名可以不同；创建硬链接时直接使用 `os.link(source_path, target_path)`，不能通过改名源文件来实现。
- 删除操作必须使用持久化的源路径与硬链接路径映射：删除硬链接使用目标路径，删除源文件或 qB 下载数据使用源路径/qB hash，禁止根据另一侧文件名猜路径。
- 后文中“重命名”若未特别说明，均指“生成目标文件名”，不是调用 qB 文件/目录重命名 API。旧版关于 `qB rename`、暂停后改名和改名回滚的条款不再适用。

第一阶段只搭建可加载、可配置、可导航、可持久化和可观察的插件框架。危险删除、硬链接执行、qB 写操作、CD2 暂停/取消和外部开关切换在对应业务真正实现并测试前，不得显示为可点击功能。

## 总体原则

- 页面上的操作必须快速响应。耗时任务放到后台执行，并显示运行中、成功数、失败数、当前项目和最终结果。
- 列表支持增量刷新或事件刷新，不要每次操作后阻塞式重载全部数据。
- 所有删除动作必须区分：只删插件记录、只删 qB 任务、删 qB 任务和下载数据、只删硬链接、只删源文件、源文件与硬链接双删。
- 所有危险删除必须二次确认，并明确显示将删除什么、不会删除什么。
- 使用稳定唯一键关联 qB 节点与 torrent hash，不能只使用种子名称。
- RSS 项目必须具备幂等去重、失败记录和单项重试能力。
- 不要把“已识别”“已存在”“已入库”“已下载”混为同一状态。
- 插件只实现功能，不复刻 V1 的独立登录、独立代理、独立日志系统、独立下载器配置或独立媒体识别服务。
- 媒体主状态固定为 `discovered`、`identified`、`unidentified`、`existing`、`pending`、`importing`、`imported`、`rolled_back`，状态转换必须经过显式状态机校验。
- 入库失败原因、库存完整度、`R` 回退标记、qB 下载状态和 CD2 watch 状态是独立字段，不得挤入媒体主状态字符串。
- SQLite 是 RSS 历史、媒体记录、qB 快照、后台任务、CD2 watch、文件清单和删除审计的事实来源；MoviePilot 插件配置只保存小型开关、连接信息和界面配置。
- 所有会被后台任务修改的记录必须使用事务、唯一约束和幂等更新，插件重启后从 SQLite 恢复非终态任务。

## 一、入库管理

### 1. 页面目标

统一展示“已发现并识别、等待人工处理、等待 CD2 定时处理、已经完成硬链接入库”的媒体。用户可以筛选、复核、修正识别、入库、检查库存完整性和执行不同级别的删除。

### 2. 状态筛选按钮

- `全部`：展示尚未进入已入库记录的全部卡片，包括已识别、已存在、未识别和待入库。
- `已识别`：媒体信息、分类、目标命名和文件明细已生成，可以入库或加入待入库队列。
- `已存在`：识别成功，但目标库存中已经存在对应目录或文件，不应默认重复入库。
- `未识别`：无法得到可靠媒体身份或分类，需要刷新识别或手动修正。
- `待入库`：已识别项目被标记为由 CD2 待入库流程处理。此状态本身不创建硬链接。
- `已入库`：已经创建硬链接并形成入库记录的项目。
- 每个筛选按钮显示真实数量；切换筛选时清空不适用于新视图的选择状态。

### 3. 类型复选框

- `电影`：勾选后显示电影；取消后隐藏电影。
- `电视剧/剧集`：勾选后显示电视剧；取消后隐藏电视剧。
- 两个复选框是独立过滤条件，可以同时勾选；若都取消则结果为空。

### 4. 卡片选择与信息

- 点击卡片切换选中状态，工具栏批量操作仅作用于选中项目。
- 卡片显示海报、标题、源名称、识别状态、电影/剧集季信息、分辨率、分类、自定义标签、大小、计划生成的新名称以及库存文件完整度。
- `P` 链接：打开该资源对应的 PT 详情页或 qB comment 中保存的来源链接。
- `T` 链接：打开对应 TMDB 电影或电视剧页面。
- `R` 标识：表示该项目此前已入库，但执行“只删硬链接”后退回已识别队列，可以重新入库。
- `!` 标识：表示自动或手动入库失败；悬停或详情中显示失败原因。

### 5. 未入库卡片右上角按钮

- `X/关闭`：只删除插件中的识别记录，不删除源文件，不删除硬链接，不操作 qB。
- `刷新`：重新读取文件信息并重新执行媒体识别、分类、命名规划和库存检查，用新结果替换当前卡片。
- `编辑`：打开手动修正窗口。

### 6. 手动修正窗口

- `类型`：电影或剧集。
- `TMDB ID`：指定正确媒体；必须是有效数字。
- `Season`：仅剧集显示，指定季号。
- `指定分类`：可选择自动采用 MoviePilot 识别分类，也可强制选择一个目录映射分类。
- `取消`：关闭窗口，不修改记录。
- `确认`：按指定 TMDB、类型、季和分类重新生成媒体信息、名称、目标相对路径和库存状态，然后更新原卡片；此操作不直接入库。

### 7. 未入库工具栏按钮

- `待入库`：仅在“已识别”视图并选中项目时可用。把项目状态改成待入库，清除上次入库失败标记，交给 CD2 CRON 或“立即处理”执行。
- `立即处理/立刻处理`：启动一次 CD2 待入库后台队列。若已有队列运行，显示“处理中”而不是重复启动。
- `追更`：读取并切换外部 Emby 追更开关。绿点表示开，红点表示关，灰点表示未知或读取失败。
- `扫库`：读取并切换外部扫库系统的开关，状态颜色规则同上。
- `刷新`：只刷新追更和扫库两个开关的当前状态，不刷新媒体卡片。
- `入库`：逐项处理选中的可入库卡片。依据分类选择目标硬链接根目录，按识别结果生成目录和文件名，通过硬链接创建媒体库文件；目标文件或库存文件已经存在时跳过，不覆盖。缺少文件明细、缺少分类或无法匹配目标路径时失败并保留卡片和原因。成功后移除识别卡片，新增已入库记录和历史记录。默认保留源文件。
- `删源`：删除选中卡片对应的源文件或整个源目录，并删除插件识别记录；不应删除已经存在的硬链接。必须醒目确认。

### 8. 已入库工具栏按钮

- `批量刷新`：重新检查选中项目的库存目录和预期文件，更新总文件数、存在数、缺失数以及“库存完整/不完整”。
- `批量入库`：V1 中该按钮没有真正实现，只会提示“暂未实现，请单个操作”。迁移插件时不得把它标为已实现。建议在真正实现前隐藏该按钮；若实现，则应对缺失硬链接执行安全补链，不覆盖已有文件。
- `只删硬链`：仅删除本次入库实际创建的硬链接，绝不删除当时因“目标已存在”而跳过的文件，也不删除源文件。删除已入库记录，并把项目恢复到“已识别”队列，附带 `R` 回退标识，便于重新入库。
- `批量双删`：删除源文件/源目录和本次创建的硬链接，再删除已入库记录；不可恢复，必须强警告确认。

### 9. 已入库单卡按钮

- `刷新`：检查一个已入库项目的库存完整性，不重新识别媒体。
- `删硬链`：行为同批量只删硬链接，并退回已识别队列。
- `删源`：只删除源文件或源目录并删除已入库记录，不删除硬链接。
- `X`：只删除插件中的已入库记录，不删除源文件或硬链接。

## 二、QB 管理

### 1. 页面目标

把 MoviePilot 中配置的多个 qBittorrent 节点汇总成媒体任务视图，展示媒体识别、库存命中、下载状态和来源信息，并允许安全地启动、删除、重新识别或人工指定媒体。

- QB 管理的自动刷新范围必须是所有已保存 VT+ RSS 任务声明的 `(QB下载器, QB分类)` 精确组合，不得扫描下载器中的全部 torrent。
- RSS 任务停用只停止调度，不移除其已有 torrent 的管理范围；删除任务或修改分类后，下次刷新必须让旧范围退出当前列表。
- 缺少 QB下载器或 QB分类的任务不形成管理范围；完全没有有效组合时刷新应明确失败并保持零扫描，禁止回退为全量扫描。
- qB category 按去除首尾空白后的完整值匹配，不使用包含匹配、前缀匹配或空分类兜底。

### 2. 分类按钮

- `已存在`：展示识别后确认库存已经存在的 qB 任务。
- `待下载`：V1 的实际含义是“所有非已存在任务”，可能包含未识别、已识别但库存不存在、暂停或下载中的任务，不应仅按 qB 下载状态理解。

### 3. 卡片行为与链接

- 点击卡片切换选中状态。
- 卡片显示识别标题、状态、季、分辨率、分类、自定义标签、qB 分类、qB 节点、源名称、大小、目标名称和库存命中情况。
- `P`：打开种子来源/PT 详情链接。
- `T`：打开对应 TMDB 页面。
- 卡片右上角 `刷新`：只刷新该 torrent 的 qB 信息并重新执行媒体识别和库存检查。
- 卡片右上角 `编辑`：手动指定电影/电视剧、TMDB ID 和季号，保存为该 torrent 的人工识别覆盖结果。

### 4. 工具栏按钮

- `刷新/识别`：从所有配置的 qB 节点读取当前任务，对新增或变化任务执行增量识别并刷新卡片。该按钮是只读识别操作，不应自动启动、删除、入库或改名。
- `开始下载`：恢复选中的 qB torrent。只在“待下载”视图可用。
- `删除任务`：从 qB 删除 torrent 任务但保留下载数据，同时移除或刷新对应插件卡片。
- `删除+文件`：从 qB 删除 torrent 并让 qB 删除下载数据。仅普通“已存在”视图提供，必须危险确认。
- `删除卡片`：只从插件本地 QB 管理列表隐藏/移除选中记录，不操作 qB torrent，不删除文件。仅“待下载”视图提供。
- `清空选择`：取消全部卡片选择，不执行其他操作。

### 5. 手动扫描已存在

- `手动`：打开一次临时扫描任务，用于扫描某个 qB 节点指定分类中的 torrent，并找出其对应媒体已经存在于库存的项目。
- `QB 节点`：选择要扫描的下载器。
- `QB 分类`：只扫描该 qB category，必填。
- `路径映射`：可选，一行一个“qB 路径前缀 => 插件可访问路径前缀”，仅用于本次扫描的路径解释。
- 扫描窗口持续显示已扫描数、总数和已存在数。
- `退出`：请求中止后台扫描，等待安全停止后展示已得到的部分结果，不丢弃已经完成的识别。
- 手动扫描结果只在当前页面临时显示；来源 `P` 链接关联可以持久保留。
- 手动模式中的 `删除任务`：只从 qB 删除任务，始终保留文件。
- `退出手动`：退出临时结果模式，恢复正常 QB 列表。

### 6. 手动识别窗口

- `类型`：电影或电视剧。
- `TMDB ID`：指定媒体，必须是数字。
- `季数`：仅电视剧显示，必须为大于等于 0 的数字；`0` 表示特别篇。不处理合集或多季包。
- `确认`：保存人工覆盖并刷新该任务识别结果；不自动启动下载或入库。

## 三、VT+

### 1. 页面结构

VT+ 包含 `站点身份`、`RSS任务`、`RSS历史` 三个子页。

- 顶部 `刷新`：在站点身份/RSS任务页重新读取当前 MoviePilot 的站点能力、qB 节点、运行配置和任务批次状态；在 RSS历史页重新查询当前历史页。
- 页面必须把调度状态、后台执行状态和历史结果分开显示。

### 2. 站点身份子页

- 插件只使用当前所在 MoviePilot 实例，不配置或访问远程 MoviePilot 节点。
- `刷新站点`：从当前 MoviePilot 的站点服务重新读取插件可用的站点身份和请求能力，不设置独立同步 CRON。
- 站点列表只读显示站点名称、域名、启用状态、适配器类型和能力状态。
- Cookie、User-Agent、passkey 和其他认证信息只允许由后端站点服务使用，禁止返回前端、写入普通历史或日志。
- 如果 MoviePilot 只能提供封装后的站点请求能力，则插件通过该能力访问详情页和搜索页，不要求用户复制 Cookie。

### 3. RSS任务的普通配置项

- `添加配置`：新增一条带默认值的 RSS 任务。
- 卡片标题旁 `+`：同样新增一条任务，不是复制当前任务。
- 卡片标题旁 `-`：从当前编辑列表删除该任务；保存前只是本地编辑，点击保存后才持久化。
- `保存配置`：保存全部 RSS 任务及其顺序和设置。
- `任务名称`：用于卡片标题、历史记录 RSS 别名和日志标识。
- `RSSURL`：RSS XML 地址。任务执行时解析标题、详情链接、种子下载链接和大小。
- `QB下载器`：选择推送目标 qB 节点。
- `RSS周期 (CRON)`：按周期拉取并处理 RSS；启动或配置变化时只对齐，不立即补跑。
- `保存路径`：添加 torrent 时传给 qB 的下载保存路径。
- `QB分类`：添加 torrent 时写入 qB category，也用于后续识别、规则选择和任务归属。
- `限制条件(名称包含)`：只有 RSS 原始标题或清洗后的标题包含该字符串时才继续处理；为空表示不过滤。
- `开始任务 CRON`：按周期扫描该 RSS 任务仍在等待的 torrent，并根据“下载”复选框恢复允许启动的任务。
- `轮询兜底 CRON`：当 qB 完成回调或实时事件遗漏时，轮询该 RSS 批次；发现下载完成后继续识别、入库登记和清理计划。
- `完成后删除任务 (分钟)`：torrent 完成后等待指定分钟再删除；0 表示不自动删除。删除文件与否由“删除文件”复选框决定。
- `上传限速 (kb/s，0=不限速)`：torrent 添加成功并确认 hash 后设置单任务上传限速；0 清除/不设置限制。
- `路径映射`：每行“源前缀 => 目标前缀”，把 qB 返回的容器路径转换为插件/MP 可访问路径，用于识别和入库；不移动文件。
- `重命名规则`：每行一条名称替换规则。仅在勾选“重命名”时应用于生成的硬链接目标文件名；先执行普通规则，再添加中文名、国配或特效标记，并保持标记位于 REMUX/版本尾标之前。不得修改 qB 源文件。
- `站点`：选择用于详情页或站内搜索的站点访问身份。只与国语/特效标签识别有关，不决定 RSS 本身从哪里读取。
- `国语关键词`：以英文逗号分隔，用于判断站点详情标签是否包含国语/国配信息。
- 状态徽标 `状态`、`待完成`、`批次量`：显示该任务最近批次的运行状态、尚未完成的 hash 数和本批次总 hash 数。
- `立即执行`：立即运行该任务一次；任务未启用、RSS URL 为空、qB 节点无效或登录失败时应明确报错。成功后显示处理、添加和待完成数量；目标文件名生成在下载完成后的入库阶段执行。

### 4. RSS任务复选框的精确语义

#### 启用任务

- 勾选：RSS CRON、开始任务 CRON、兜底 CRON均可参与调度，也允许“立即执行”。
- 取消：整个任务停用，三个周期都跳过，“立即执行”也应拒绝；已有 qB torrent 不被自动删除或停止。

#### 添加种子时暂停

- 勾选：torrent 加入 qB 时处于暂停状态，等待“开始任务 CRON”配合“下载”选项决定是否恢复。
- 取消：torrent 交给 qB 后立即按 qB 自身规则开始；此时即使没有勾选“下载”，qB 也可能自行下载，所以界面必须提示两者区别。

#### 推送种子文件

- 勾选：优先使用站点 Cookie/UA 下载 `.torrent` 文件，再把文件上传给 qB；若失败，再尝试把种子 URL 交给 qB。
- 取消：优先把 URL 交给 qB；若失败，再回退到下载 `.torrent` 后上传。
- 该选项控制优先方式，不是禁止另一种方式。

#### 识别国语

- 勾选：torrent 已成功加入 qB 后，读取所选站点的当前种子标签，命中“国语关键词”时为后续硬链接目标文件名添加 `-国配`。
- V1 对已确认的“华语电影”跳过国语检测；对外语电影、动画电影、未识别或未分类项目执行检测。
- UBits 直接读取 RSS 详情页的当前种子标签；CHD/HDSKY 先按清洗后的种子标题站内搜索，多结果时必须用 RSS 链接中的种子 ID 精确定位，否则跳过，不能猜测。
- 未选择站点、站点请求失败、未命中标签时不改名，并在历史中说明跳过或未命中原因。

#### 识别特效

- 勾选：用所选站点的标签检查“特效/特效字幕”，命中后为后续硬链接目标文件名添加 `-特效`。
- 可与“识别国语”同时勾选，二者同时命中时都添加，并保持稳定顺序。
- 只有种子已经成功推送到 qB 且站点可用时才执行。

#### 添加中文标题

- 勾选：从 RSS 标题第一个顶层方括号内容中提取有效中文别名，过滤蓝光、REMUX、字幕、国配、特效等噪声词；在生成硬链接目标文件名时加上 `[中文名].` 前缀。该选项不修改 qB 下载文件。
- 该步骤独立于国语/特效标签识别，不要求站点命中标签。
- 已有同样前缀或已有有效中文名称时不重复添加。

#### 入库

- 勾选：torrent 下载完成并识别后，把结果送入“入库管理”的识别/待处理链，允许后续硬链接入库。
- 取消：仍可在 qB 中下载和管理，但下载完成结果不得自动进入入库队列。
- 此选项不是“RSS 添加后立刻创建硬链接”，必须等下载完成且文件信息可用。

#### 目标文件名生成

- 勾选：下载完成后，根据 MoviePilot 命名模板、重命名规则、自定义识别词、中文标题、国配和特效标记生成硬链接目标文件名；qB 源文件和目录保持原名原路径。
- 取消：不执行普通重命名规则；其他命名输入仍可按各自选项参与目标文件名生成，但不得修改 qB 源文件。

#### 下载

- 勾选：允许插件在“开始任务 CRON”到点时恢复该任务批次中尚未完成且可恢复的 qB torrent。
- 取消：插件不主动恢复 torrent。
- 它不等于强制暂停。若“添加种子时暂停”未勾选，qB 仍可能在添加后立即下载。

#### 删除文件

- 勾选：仅当“完成后删除任务分钟数”大于 0 时，定时删除 qB torrent 任务和其下载数据。
- 取消：到期时只删除 qB torrent 任务，保留下载数据。
- 当删除分钟数为 0 时，此复选框没有实际动作。

### 5. RSS处理流程

1. 按 CRON 或手动触发读取 RSS。
2. 为每个 RSS 项生成稳定去重键；正常周期中已经有历史记录的项目直接跳过。
3. 检查种子链接和名称包含限制。
4. 按“推送种子文件”的优先级把种子加入指定 qB，并设置保存路径、分类和初始暂停状态。
5. 区分重复、配置错误和临时网络失败；临时错误可以有限重试，重复项记为跳过。
6. 获取新 torrent hash，设置上传限速，保存来源链接。
7. 根据 MoviePilot 命名规则生成硬链接目标文件名；不修改 qB 下载文件。
8. 建立该 RSS 批次的 hash 监控，并立即做一次识别快照。
9. 开始 CRON负责恢复任务；完成事件或兜底 CRON负责确认完成、进入入库链和安排延时删除。

### 6. RSS历史子页

- 表格显示 RSS 任务别名、种子名称、大小、记录时间、删除时间、状态和操作。
- `筛选`：按种子名称关键词查询，并回到第一页。
- `清空`：清除关键词并回到第一页。
- `刷新`：保留当前页和关键词重新查询。
- `打开`：打开 RSS 项详情链接。
- `重试`：仅在状态含“拒绝原因”或失败标记时显示，只重跑这一条 RSS 项，允许绕过去重记录；完成后显示 processed、added、skipped、errors 并刷新历史。
- `上一页/页码/下一页`：标准分页，边界页禁用对应按钮。

## 四、CD2 设置与待入库流程

### 1. 配置项

- `CD2 gRPC 地址`：CloudDrive2 gRPC 服务地址，例如 `主机:端口`。用于查询云挂载、监听上传事件、轮询上传列表以及暂停/取消异常上传。
- `CD2 访问令牌`：调用 CD2 gRPC 的授权令牌。
- `云类型名`：从 CD2 云列表回填的挂载类型/名称。
- `云账号ID`：从 CD2 云列表回填的账号标识。
- 重要现状：V1 会保存“云类型名”和“云账号ID”，但当前待入库和上传监控流程并未真正读取它们。迁移插件时不要宣称这两个值已经控制上传；若 MP/CD2 API 确实需要它们，应在新插件中定义清楚用途，否则标为只读信息或移除。
- `待入库 CRON`：周期性处理“待入库”队列，默认每天 01:00。服务启动或配置改变时只对齐，不立即补跑。
- `追更 Emby 地址`：承载追更开关页面的 Emby 地址。
- `追更 PageId`：追更设置页面或开关所在页面标识。
- `追更 Token`：读取和切换追更状态的授权信息。
- `扫库系统地址`：外部扫库管理服务地址。
- `扫库账号/密码`：用于登录扫库系统并取得 JWT。
- `扫库配置名`：要控制的扫库配置。
- `扫库节点名`：要控制或通知的媒体库节点。
- `扫库 JWT Token`：只读展示当前获取并保存的令牌。
- `CD2 CRON 触发时追更`：`不操作`保留当前状态，`开启`要求 CRON 前确保开启，`关闭`要求 CRON 前确保关闭。
- `CD2 CRON 触发时扫库`：语义同上，作用于扫库开关。

### 2. 按钮

- `获取扫库 Token`：用扫库地址、账号和密码登录，获取并保存 JWT，再回填只读 Token 字段。
- `拉取 CD2 云列表`：要求先填 gRPC 地址和令牌；查询 CD2 当前云挂载并显示名称、账号和路径。如果尚未填写云类型名，自动用第一项回填。
- 云卡片 `使用`：把该云挂载的名称和账号标识回填到“云类型名/云账号ID”，不代表已经保存，仍需点击保存。
- `保存 CD2 配置`：持久化本页全部字段。

### 3. CD2 待入库业务流程

1. CRON 到点时先检查是否真实存在待入库或正在入库项目；没有任务则不切换追更/扫库，也不启动空队列。
2. 读取追更和扫库当前状态，按两个模式设置目标状态并再次校验。任一状态无法读取、设置失败或校验不一致，本轮入库中止。
3. 串行处理待入库卡片，避免同时创建大量硬链接和上传任务。
4. 每项先执行与入库管理相同的硬链接入库，默认不删源；失败则回到已识别并保存失败原因。
5. 入库成功后按完整 `destPath + size + 时间窗`发现 CD2 上传任务，绑定 `UploadFileInfo.key` 后只用 key 跟踪，不得按文件名关联。
6. 优先监听 CD2 PushMessage 作为唤醒信号；推送接口不可用时使用上传列表轮询兜底。
7. 若发现 CD2 开始真实传输而不是预期的快速云端处理，暂停并取消相关上传，只删除本次硬链接，保留源文件，把卡片回退，避免持续上传占用带宽。
8. 若发现风控、限流、验证码、Forbidden、rate limit 等风险错误，同样暂停/取消、只删硬链接回退，并停止本轮后续待入库项目，同时发送告警。
9. 全部成功且没有剩余监控时通知 Emby 扫库；若本轮全部失败或全部回退，则直接恢复相关开关。后续回调完成后也应恢复本轮临时改变的开关状态。

## 五、外部接口的精确契约

### 1. CloudDrive2 gRPC

- 插件目录必须附带与 V1 同源的 `clouddrive.proto`，文件名固定为 `clouddrive.proto`。
- 连接方式：`grpc.insecure_channel(CD2_GRPC_ADDR)`；每个授权 RPC 携带 metadata：`authorization: Bearer <CD2_TOKEN>`。
- 本插件实际需要的 RPC：
  - `GetAllCloudApis(Empty) -> CloudAPIList`：读取云挂载列表。使用 `name`、`userName`、`nickName`、`path`、`isLocked`。
  - `GetUploadFileList(GetUploadFileListRequest) -> GetUploadFileListResult`：分页读取上传任务。必须读取 `key`、`destPath`、`size`、`transferedBytes`、`status`、`errorMessage`、`operatorType`、`statusEnum`。
  - `PauseUploadFiles(MultpleUploadFileKeyRequest)`：按 CD2 任务 key 暂停上传。
  - `CancelUploadFiles(MultpleUploadFileKeyRequest)`：按 CD2 任务 key 取消上传。
  - `PushMessage(Empty) -> stream CloudDrivePushMessage`：只作为“上传列表可能变化”的唤醒信号，不能仅凭消息本身判定某个文件成功。
- `UploadFileInfo.Status`：`WaitforPreprocessing=0`、`Preprocessing=1`、`Cancelled=2`、`Transfer=3`、`Pause=4`、`Finish=5`、`Skipped=6`、`Inqueue=7`、`Ignored=8`、`Error=9`、`FatalError=10`。

### 2. 追更开关 API

追更开关实际是 Emby 插件配置页中的 `GeneralOptions.CatchupMode`，不是通用 Emby 用户设置。

#### 读取状态

- 方法：`GET`
- URL：`{emby_catchup_base_url}/emby/UI/View`
- Query：
  - `PageId={emby_catchup_page_id}`
  - `ClientLocale=zh-cn`
  - `X-Emby-Token={emby_catchup_token}`
- Headers：
  - `X-Emby-Token: <token>`
  - `X-Emby-Client: MediaFlow`
  - `X-Emby-Device-Id: mediaflow-pro`
  - `X-Emby-Device-Name: MediaFlow`
  - `X-Emby-Version: 1.0.0`
- 状态字段：`response.EditObjectContainer.Object.GeneralOptions.CatchupMode`。
- 同时保存响应中的 `PageId`、`PluginId` 和完整 `EditObjectContainer.Object`，切换时必须提交完整对象，不能只提交一个布尔值。

#### 设置状态

1. 先调用读取接口取得最新配置对象。
2. 只修改 `Object.GeneralOptions.CatchupMode = true/false`。
3. 方法：`POST`。
4. URL：`{emby_catchup_base_url}/emby/UI/Command?X-Emby-Token={token}`。
5. Header 额外包含 `Content-Type: application/json`。
6. JSON Body：

```json
{
  "ClientLocale": "zh-cn",
  "CommandId": "PageSave",
  "Data": "<修改后的完整 Object JSON 字符串>",
  "ItemId": "<读取响应中的 PluginId，缺失时为 undefined>",
  "PageId": "<读取响应中的 PageId 或配置值>"
}
```

7. 保存后再次读取并验证 `CatchupMode` 与目标值一致；验证失败按操作失败处理。

### 3. 扫库系统 API

#### 登录并取得 JWT

- 方法：`POST`
- URL：`{emby_scan_base_url}/api/v1/login/access-token`
- Body 类型：`application/x-www-form-urlencoded`
- 字段：`username`、`password`
- 成功条件：HTTP 200 且 JSON 中存在非空 `access_token`。
- 读取配置遇到 HTTP 401/403 时，只允许自动重新登录一次，然后重试原请求一次。

#### 读取扫库开关

- 方法：`GET`
- URL：`{emby_scan_base_url}/api/v1/system/settings/{emby_scan_setting_name}`
- Header：`Authorization: Bearer <JWT>`。
- 响应允许三种格式：直接数组、`{"settings": [...]}`、`{"message": [...]}`。
- 按 `row.name == emby_scan_target_name` 精确查找节点。
- 当前状态字段：目标节点的 `switch`，按布尔值解析；找不到节点必须报错，不能默认关闭。

#### 切换扫库开关

1. 先读取完整设置列表。
2. 只修改目标节点的 `switch`。
3. 方法：`POST`。
4. URL：`{emby_scan_base_url}/api/v1/system/save_settings`。
5. Headers：`Authorization: Bearer <JWT>`、`Content-Type: application/json`。
6. JSON Body：`{"settings": <修改后的完整列表>, "name": "<emby_scan_setting_name>"}`。
7. 保存后重新读取并验证目标节点的 `switch`。

#### 通知 Emby 扫库

- 从扫库设置列表中找到目标节点，读取该节点的 `host` 和 `api_key`。
- 方法：`POST`。
- URL：`{node.host}/emby/Library/Refresh?api_key={node.api_key}`。
- HTTP 200、202 或 204 均视为已接受；其他状态为失败。
- 该接口只是发起 Emby 媒体库刷新，不等于刷新已经完成。完成判断应继续使用回调或 Emby 计划任务状态。

## 六、UBits、CHD 和 HDSKY 标签解析契约

### 1. 通用规则

- 站点规则匹配优先级：MP `site_key` 绑定、站点名称别名、URL host。
- 请求必须通过 MoviePilot 的站点访问能力携带正确 Cookie、User-Agent 和 Referer，不在页面或日志输出 Cookie。
- 搜索标题先 HTML 解码、去 CDATA、合并连续空白，再从第一个 `[` 或 `【` 开始截断，只保留主标题。
- CHD/HDSKY 搜索 URL：`{site_base}/torrents.php?search={URL编码后的清洗标题}`。
- 从搜索 HTML 中定位所有 `details.php?id=<数字>`，每个候选只分析该链接附近的种子块；候选块必须包含 `torrentname`、`optiontag` 或 class 为 `tag` 的标签结构之一。
- 搜索结果只有一条时使用该条；多条时必须从 RSS 详情链接提取 `id` 并精确匹配。RSS 无 ID 或 ID 未命中时返回 `skip`，禁止选择第一条猜测。
- 同一站点两次请求至少间隔 60 秒。HTTP 403、429、503 视为站点风控，首次命中后进入 300 秒冷却，只再尝试一次。

### 2. UBits

- 识别方式：不做站内搜索，优先直接访问 RSS 的详情链接。
- 若 RSS 链接不是标准详情页但能提取数字 ID，则重建为 `{site_base}/details.php?id={id}`。
- 只分析详情页“标签/Tags”表格行：优先匹配 `td.rowhead` 为“标签/Tags”，取对应 `td.rowfollow`；兼容普通相邻 `td`。
- 若表格行无法定位，只允许扫描 HTML 前 20000 字符且其中必须出现 tag class，避免误命中推荐种子或相关资源。
- 国语命中：标签区存在 query 参数 `tag_id5=1`，或 `span` 的 class 包含 `tag` 且文本包含配置的国语关键词。
- 特效命中：`span` 的 class 包含 `tag` 且文本包含“特效”或“特效字幕”。

### 3. CHD / PTCHDBits

- 站点名称别名：`ptchdbits`、`chdbits`、`ptchd`、`彩虹`；host 包括 `ptchdbits.co`、`ptchdbits.net`。
- 识别方式：按清洗标题搜索，再按 RSS torrent ID 消歧。
- 国语命中：候选种子块中 `div` 的 class 包含 `tag-gy`，且文本命中国语关键词。
- 特效命中：候选块出现 class 包含 `tag-txsub` 即命中；同时兼容该 `div` 文本包含“特效/特效字幕”。

### 4. HDSKY

- 站点名称别名：`hdsky`、`hd sky`、`天空`；host 为 `hdsky.me`。
- 识别方式：按清洗标题搜索，再按 RSS torrent ID 消歧。
- 国语命中：候选种子块中 `span` 的 class 包含 `optiontag`，文本命中国语关键词。
- 特效命中：同一 `optiontag` 文本命中“特效/特效字幕”。

### 5. 解析结果

- `ok`：成功定位目标种子并完成标签检查，可以分别返回 `has_cn`、`has_fx`。
- `miss`：搜索页中没有种子候选，属于未命中，不改名。
- `skip`：缺少站点、详情/搜索请求失败、多结果无法精确定位或标签区无法确定，不改名并记录原因。
- HTML 结构变化必须产生可观察的 `skip`，不能把整页任意文本包含关键词当作命中。

## 七、RSS 去重、安全、重命名与重试契约

### 1. V1 现状与必须修正的问题

- V1 的历史键是 `task_id + (GUID 优先，否则 enclosure URL，否则详情 URL，否则标题)`，使用原始字符串，不规范化 URL，也没有 passkey 脱敏。
- MP 插件禁止原样沿用该键。必须采用“来源身份键”和“qB 内容键”两级去重。

### 2. 来源身份键

- 每条 RSS 项先计算 `source_identity`，优先级固定如下：
  1. 能从 GUID、详情 URL 或 enclosure URL 提取站点 torrent ID：`site_key:torrent_id:<id>`。
  2. GUID 是稳定的非 URL opaque ID：`site_key:guid:<guid>`。
  3. 规范化后的 enclosure URL：`site_key:enclosure:<canonical_url>`。
  4. 规范化后的详情 URL：`site_key:detail:<canonical_url>`。
  5. 最后兜底：`site_key:fallback:<规范化标题>|<规范化发布时间>`。
- 历史唯一键：`SHA-256(task_id + "\n" + source_identity)`；用于同一 RSS 任务内的幂等。
- 不同 RSS 任务可以各自保留历史，但 torrent 推送前还必须做全局内容去重。

### 3. qB 内容键

- 下载到 `.torrent` 文件后，应解析 bencode `info` 字典并计算 BitTorrent v1 info-hash；支持 v2 时同时记录 v2 hash。
- 全局唯一约束：`downloader_id + info_hash`。同一下载器已经存在该 hash 时标记 duplicate，不再次添加。
- 若以 URL 方式添加且添加前无法取得 hash，添加后必须从 qB 返回/列表解析 hash，并把之前的 `source_identity` 绑定到该 hash。
- 种子 ID、GUID、详情 URL、下载 URL只是同一内容的别名；一旦得到 info-hash，以 info-hash 为最终内容身份。

### 4. URL 规范化和脱敏

- 规范化：scheme 和 host 转小写、移除 fragment、移除默认端口、规范化重复斜线、稳定排序非敏感 query 参数。
- 下列 query key 及大小写变体视为敏感：`passkey`、`authkey`、`torrent_pass`、`token`、`access_token`、`api_key`、`apikey`、`rsskey`、`secret`、`signature`、`sign`、`uid`。
- 计算去重 URL 时完全移除敏感参数的值；页面和日志中保留参数名但值显示为 `***`。
- 原始带密钥 URL只允许存在于执行请求所需的内存或加密配置中；不得写入普通历史表、任务消息、异常文本、浏览器 DOM、通知和日志。
- 捕获网络异常前先对异常文本做 URL 脱敏，防止 requests/httpx 把完整 URL带入错误消息。

### 5. 目标文件名规则语法

- 规则按 qB category 分组：`[分类名]` 开始一个规则组。
- 普通替换：`旧文本 => 新文本`，按出现顺序执行全量字面替换。
- 正则替换：`/pattern/im => replacement`。支持 `i` 和 `m` 标志；replacement 使用 Python 风格 `\1` 或 `\g<name>` 捕获组，不使用 JavaScript `$1`。
- 正则编译失败时整条规则禁用并显示配置错误，不能静默当普通文本处理。
- 所有规则按配置顺序作用于目标文件名；普通规则完成后再执行中文标题、`-国配`、`-特效`，最后做 REMUX/版本尾标顺序归一化。规则计算结果写入 `new_rel`，不调用 qB 重命名 API。

### 6. 目标文件名安全

- 先生成完整 target plan，再创建硬链接。计划必须包含源路径、目标路径、对象类型和最终文件名。
- 文件扩展名默认保留；规则只作用于文件名 stem。若未来允许修改扩展名，必须是单独的显式选项。
- 拒绝空名称、`.`、`..`、绝对路径、路径穿越、NUL、控制字符以及 `<>:\"/\\|?*`；清理尾部空格和点。
- 冲突检查覆盖：torrent 内两个对象改成同一路径、目标路径已经存在、仅大小写变化导致的平台冲突。默认策略是 `fail_before_apply`，发现任一冲突则整批不执行，禁止覆盖。
- 多文件 torrent：按源文件清单生成各自的目标相对路径；目录不存在时创建目标目录，然后逐个创建硬链接。
- 任一硬链接创建失败时停止后续步骤，删除本次已经创建且可验证属于本次 watch 的目标硬链接；源文件保持不变。
- 目标已存在、目标路径冲突、非法名称或跨文件系统时禁止覆盖或复制，并记录明确失败原因。
- qB 任务处于下载、检查、移动或分配空间状态时，不执行硬链接；必须等源文件稳定且下载完成。

### 7. 重试矩阵

- RSS feed GET：最多 3 次总请求，退避 3 秒、10 秒；仅连接失败、超时、HTTP 408/425/429/500/502/503/504 重试。
- `.torrent` 下载：最多 3 次总请求，退避 3 秒、10 秒；网络临时错误和上述 HTTP 状态重试。HTTP 401/403 视为站点认证/配置问题，不做快速重试。
- qB 添加 torrent：每种推送模式最多 4 次总请求，退避 3 秒、10 秒、30 秒。首选模式耗尽后只切换一次备用模式，因此理论上最多 8 次请求。
- qB 可重试错误：HTTP 408/425/429/500/502/503/504，连接/超时/SSL 错误，或 qB HTTP 200 但正文以 `Fails` 开头/包含明确临时 `error`。
- qB 不重试错误：duplicate、HTTP 401/403、无效保存路径、无效分类、确定性参数错误。duplicate 应查找并记录已有 hash。
- 站点详情/搜索：最多 2 次总请求；只有 HTTP 403/429/503 在 300 秒 host 冷却后允许第二次。禁止在风控时快速循环请求。
- 硬链接创建：确定性冲突、非法名称和跨文件系统错误不重试；源文件列表短暂未刷新时可重新读取一次，不做无限重试。
- 所有重试必须记录 attempt、next_retry_at、最终错误类别；日志中的 URL必须脱敏。

## 八、五类路径、硬链接和 CD2 监控契约

### 1. 五类路径定义

1. `qb_reported_path`：qB API 返回的 `content_path/save_path`，属于 qB 容器的路径命名空间，例如 `/downloads/series/A`。
2. `plugin_source_path`：应用路径映射后，MoviePilot 插件进程实际可以访问的源文件路径，例如 `/data/downloads/series/A`。
3. `local_hardlink_path`：插件创建硬链接的本地 CD2 staging 路径，例如 `/data/cd2-staging/TV/标题...mkv`。
4. `mp_library_path`：MoviePilot/Emby 用于库存检查和媒体库扫描的最终 STRM 挂载目录，例如 `/media/TV/标题...strm`。
5. `cd2_dest_path`：CD2 上传任务中的完整云端目标路径，例如 `/CloudDrive/Media/TV/标题...mkv`。

### 2. 正常部署关系

- `qb_reported_path -> plugin_source_path` 通过最长前缀路径映射完成。映射后必须验证真实存在且不能逃出允许源根目录。
- `plugin_source_path` 与 `local_hardlink_path` 必须位于同一宿主文件系统/存储卷。启动时用文件系统 device ID 和一次临时硬链接探针验证，失败则禁止入库，绝不退化成复制。
- `local_hardlink_path` 必须位于 CD2 正在监控或挂载上传的本地目录树中；CD2 容器看到的路径可以不同，但必须配置显式 `plugin_staging_root -> cd2_staging_root` 映射。
- `local_hardlink_path` 的相对路径必须稳定映射到 `cd2_dest_path`：`cd2_dest_root + relative(local_hardlink_path, plugin_staging_root)`。
- `mp_library_path` 是 CD2 云端目录重新挂载给 MoviePilot/Emby 后的路径，配置显式 `cd2_dest_root -> mp_library_root` 映射。库存检查在 `mp_library_path` 上进行，不应把 staging 目录当作最终媒体库。
- 库存检查必须由插件直接读取 `mp_library_path` 下的本地目录和文件，其中库存文件只接受 `.strm`；不得用 MoviePilot/Emby 的“媒体已存在”接口替代本地文件检查。按 MP 分类定位库存根目录后，优先通过一级目录中的 `[tmdbid=ID]` 或 `{tmdbid=ID}` 锁定媒体目录；未命中时才按 MoviePilot 预期目录名进行不区分大小写的完整匹配。锁定目录后提取库存标题时，必须同时移除 TMDB 标记、模板年份和年份前后的尾部分隔符，避免把 `标题 (2026) -`再次交给 MoviePilot 生成重复年份。随后重新调用 MoviePilot 当前命名模板和自定义识别词生成完整 `new_rel`，库存预期路径只将最终扩展名派生为 `.strm`。库存比较不使用源媒体大小；优先匹配精确相对路径，再比较去掉库存标题和扩展名后的完整文件特征。根目录未配置、挂载不可访问、重复 TMDB 目录、媒体目录缺失、部分文件缺失和空资源必须分别记录，挂载离线不得误判为库存缺失。
- 因此正常数据链是：qB 下载文件 -> 插件可访问源路径 -> 同盘 staging 硬链接 -> CD2 云端目标 -> CD2/网盘挂载的 MP 媒体库。

### 3. 建议的容器挂载示例

```text
宿主同一存储卷:
  /volume1/media/downloads       qB下载源
  /volume1/media/cd2-staging     本地硬链接与CD2上传源

qB容器:
  /volume1/media/downloads -> /downloads

MoviePilot容器:
  /volume1/media/downloads -> /data/downloads
  /volume1/media/cd2-staging -> /data/cd2-staging
  CD2最终媒体挂载 -> /media

CD2容器:
  /volume1/media/cd2-staging -> /local/cd2-staging
  云端目标根 -> /CloudDrive/Media

映射:
  /downloads -> /data/downloads
  /data/cd2-staging -> /local/cd2-staging
  /local/cd2-staging/<rel> -> /CloudDrive/Media/<rel>
  /CloudDrive/Media/<rel> -> /media/<rel>
```

### 4. 当前 MoviePilot 部署的默认目录配置

当前 MoviePilot 容器挂载为：

```text
/volume1/media/transmission -> /MP
/volume2/SSD                -> /SSD
```

插件配置页必须提供可编辑的 `inventory_root` 和 `source_routes`，不能把这些路径只写死在代码中。默认配置如下：

```yaml
inventory_root: /SSD/云盘/strm/影视库
source_routes:
  - name: UP
    prefix: /MP
    link_roots:
      movie: /MP/电影UP
      series: /MP/剧集UP
    enabled: true
  - name: SSD
    prefix: /SSD
    link_roots:
      default: /SSD/云盘/l
    enabled: true
```

- 所有配置路径都是 MoviePilot 插件容器内路径，不是 NAS 宿主机路径。
- 不提供电影/剧集分类白名单选择框。`movie` 和 `series` 根目录默认覆盖 MoviePilot 返回的全部分类。
- MoviePilot 识别为电影时使用 `movie` 根目录，识别为剧集时使用 `series` 根目录；当前 `纪录片` 由 MoviePilot 识别为剧集，因此自动走剧集根目录。
- 最终库存目录：`inventory_root / MP分类 / MoviePilot目标相对路径`，最终文件扩展名统一派生为 `.strm`。
- 硬链接目录：`命中的link_root / MP分类 / MoviePilot目标相对路径`，保留 MoviePilot 命名结果中的真实媒体扩展名。
- MoviePilot 命名必须使用文件名、父目录和上上级目录的完整路径上下文，并自动应用宿主当前电影/电视剧命名模板、自定义识别词及命名字典。插件不得自行拼接简化的“标题 + 季集 + 分辨率”文件名。
- 每个源文件至少保存 `src_file`、`new_rel`、派生的 STRM 库存相对路径、`inventory_exists`、匹配方式和实际匹配路径。执行入库时跳过 `inventory_exists=true` 的文件，只处理缺失文件。
- 源路由按路径边界感知的最长前缀匹配；`/SSD` 可以命中 `/SSD/downloads/A`，但不能命中 `/SSD2/A`。
- 路由可分别提供 `movie`、`series` 根目录，也可用 `default` 作为共同根目录。
- MP 分类只要是安全的单级目录名称即可参与路径规划；分类为空或包含路径分隔/目录穿越时必须拒绝。
- 即使源路径没有命中硬链接路由，只要库存根目录和分类有效，仍可执行最终媒体库本地库存检查。

### 5. CD2 任务关联键

- 禁止只按文件名关联 CD2 上传任务，同名电影、同集不同版本和多目录同名文件都会误匹配。
- 创建硬链接时为每个文件持久化：`watch_id`、`imported_id`、`plugin_source_path`、`local_hardlink_path`、`expected_cd2_dest_path`、`expected_mp_library_path`、文件大小、创建时间和内容 hash（可用时）。
- 初次匹配 CD2 列表使用：规范化后的完整 `destPath + size + watch时间窗`。
- 一旦发现匹配行，立即持久化 CD2 `UploadFileInfo.key`；后续状态、暂停和取消全部以 `key` 为主键，完整路径只用于重启后的重新发现。
- 多文件入库必须保存每个文件自己的 CD2 key 和状态，整张卡片只有在所有文件达到终态后才能完成。

### 6. 成功、真实传输与超时

- CD2 成功状态：匹配任务进入 `Finish` 或 `Skipped`，没有风险错误，并且从未超过真实传输阈值；或者已观察到成功终态后任务从列表消失。
- 真实传输字节阈值默认：`max(8 MiB, min(64 MiB, file_size * 1%))`，允许配置。
- `Transfer` 状态先进入 20 秒 grace period；满足任一条件即认定非秒传并回退：
  - `transferedBytes >= 真实传输字节阈值`；
  - `Transfer` 连续存在超过 20 秒且 `transferedBytes` 持续增长。
- 仅看到一次瞬时 `Transfer` 且字节未超过阈值不能立刻删除硬链接，应继续观察。
- 上传任务出现超时默认 180 秒：在该时间内未发现 `expected_cd2_dest_path` 对应任务则回退本次硬链接。
- 单卡最终超时默认 7200 秒；超时后暂停/取消已知 key、只删本次硬链接、保留源文件并标记可重试。
- 活跃任务轮询 10 秒；PushMessage 不可用时兜底轮询 30 秒；没有监控任务时 300 秒。参数可配置但必须有上下限。

### 7. 重启恢复

- 监控状态必须持久化，不能只放内存。至少包含 `waiting_task`、`watching`、`rolling_back`、`done`、`rolled_back`、`risk_control`、`error`。
- 插件启动时加载所有非终态 watch：
  1. 已有 CD2 key：直接按 key 对账。
  2. 无 key：按完整 `destPath + size + 创建时间窗`重新发现并绑定 key。
  3. 已是 `Finish/Skipped`：验证最终媒体库路径后标记完成。
  4. 已跨真实传输阈值或命中风控：继续幂等回退。
  5. 状态为 `rolling_back`：继续暂停、取消和只删硬链接；每一步可重复执行。
- 删除硬链接前必须验证该路径属于本 watch、inode/文件标识与创建记录一致且位于 staging 根目录；永远不删除源路径或 MP 最终媒体库中的既有文件。
- 完成后验证 `mp_library_path` 出现并符合预期大小，再通知 Emby 扫库。CD2 任务成功但最终挂载文件迟迟不可见时保持 `waiting_library`，不能提前宣称入库完成。

## 九、MoviePilot 复用要求

- 下载器：只枚举当前 MoviePilot 已配置的 qBittorrent 实例，不维护独立 qB 用户名密码页面；Transmission 等不具备所需能力的下载器不进入选择列表。
- 识别：使用 MP 的媒体识别、TMDB 数据、分类和命名能力；插件只保存人工覆盖和本插件需要的业务状态。
- 站点：使用 MP 的站点服务发起带认证的详情页/搜索请求，不在插件页面明文展示 Cookie。
- 调度：使用 MP 插件调度器注册 RSS、启动、兜底和 CD2 待入库任务，并防止同一任务重入；站点身份不设置独立同步任务。
- 文件：使用 MP 的目录映射和存储抽象；硬链接前必须验证源和目标支持硬链接，禁止静默退化为复制。
- 通知：使用 MP 通知渠道报告批量结果、qB 登录失败、RSS 临时失败、CD2 风控和回退结果。
- 前端：使用 Vue 模块联邦；`AppPage.vue` 承载入库管理、QB 管理和 VT+ 全页工作区，`Page.vue` 提供插件详情摘要，`Config.vue` 提供全局与外部集成配置。
- 数据：使用插件数据目录中的 SQLite 保存 RSS 历史、人工识别覆盖、批次监控、入库记录和删除审计；小型开关和连接配置继续使用 MoviePilot 插件配置。所有记录必须能追溯到节点、hash、源路径和任务。

## 十、验收标准

- 上述每个可见按钮和配置项都有明确可验证的行为，不允许空按钮或把“暂未实现”包装成成功。
- VT+ 的九个复选框可以单独和组合测试，特别验证“暂停”和“下载”的独立关系。
- 同一 RSS 项重复执行不会重复添加 torrent；失败历史可以单项重试。
- 同一内容即使 GUID、详情 URL 和下载 URL不同，也会在取得 info-hash 后合并为同一内容；任何页面和日志均看不到 passkey。
- 普通替换和正则替换分别通过测试；非法目标名称、目标路径冲突、多文件目标规划、跨文件系统拒绝和部分硬链接失败回滚都有验收用例，且测试确认 qB 源文件名不发生变化。
- 只删记录、删 qB 任务、删 qB 文件、删硬链接、删源和双删的边界完全不同且经过测试。
- 只删硬链接不会删除原本已存在而被跳过的库存文件，并能恢复已识别卡片。
- 手动刷新/识别不会触发启动、删除、入库或其他隐式副作用。
- CD2 无待入库任务时不切换 Emby 开关；开关校验失败时不开始入库。
- CD2 风控或真实传输回退时保留源文件、取消上传、删除本次硬链接并停止后续队列。
- CD2 关联以完整目标路径和任务 key 为主，不以文件名为主；同名文件、多文件任务和服务重启均能正确恢复。
- 部署检查能证明源路径和 staging 硬链接路径位于同一文件系统，并能完整解释五类路径的映射关系。
- 所有后台任务可观察、可防重入、失败可恢复，页面操作不因全量扫描而长时间卡死。
