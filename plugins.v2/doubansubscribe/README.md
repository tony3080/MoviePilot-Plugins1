# 豆瓣订阅助手

插件 ID：`DoubanSubscribe`

从用户填写的 RSS 地址读取电视剧条目，取得豆瓣详情中的总集数，匹配 TMDB 作品与季度，并创建 MoviePilot 订阅。

## 工作流程

1. 解析 RSS 2.0 或 Atom 条目，优先从豆瓣链接提取 `subject` ID。
2. 通过 MoviePilot 的豆瓣接口读取详情；豆瓣未明确声明总集数时停止处理该条目。
3. 同时生成完整标题和“基础标题 + 季号”候选，检索并评分 TMDB 结果。
4. 只有最高分达到阈值且明显领先第二名时，才确定 `tmdb_id + season`。
5. 创建订阅时将豆瓣总集数写入 `total_episode` 和 `lack_episode`，并设置 `manual_total_episode=1`。
6. 创建后重新读取数据库，确认集数和锁定标记均已保存。

锁定使用 MoviePilot 自身的“手动修改过总集数”字段。MoviePilot 后续刷新元数据时会保留该总集数，不会用 TMDB 集数覆盖。要求 MoviePilot `2.15.1` 或更高版本。

## 配置

- `RSS 地址`：每行一个 `http` 或 `https` 地址，默认示例为 `http://192.168.110.31:9150/rsshub/hot_tv`。
- `执行周期`：五段 Cron，默认每 6 小时执行一次。
- `每个 RSS 最大条目数`：单次从每个地址处理的上限，默认 50。
- `最低匹配分`：候选必须达到的最低可信分，默认 80。
- `最低领先分`：第一名相对第二名必须领先的分数，默认 15。
- `RSS 使用代理`：仅影响 RSS 请求；内网 RSS 地址通常不要开启。

插件会保留最近 500 条处理记录。成功创建或已经存在的条目会去重；失败和歧义条目会在后续运行中重试。

## 安全边界

- 不使用 TMDB 集数代替豆瓣总集数。
- 豆瓣总集数缺失、TMDB 得分不足或候选过于接近时，不创建订阅。
- MoviePilot 已存在相同 `tmdb_id + season` 的订阅时，只记录现状，不修改原订阅。

详细匹配算法与风险分析见仓库根目录的 `豆瓣接口与TMDB电视剧匹配设计.md`。
