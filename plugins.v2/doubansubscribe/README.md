# 豆瓣订阅助手

插件 ID：`DoubanSubscribe`

从用户填写的 RSS 地址读取电视剧条目，取得豆瓣详情中的总集数，匹配 TMDB 作品与季度，并创建 MoviePilot 订阅。

## 工作流程

1. 解析 RSS 2.0 或 Atom 条目，优先从豆瓣链接提取 `subject` ID。
2. 通过 MoviePilot 的豆瓣接口读取详情，先按国家或地区分为国产剧、欧美剧、日韩剧或其他地区，并按设置过滤。
3. 豆瓣未明确声明总集数时，先判断是否已经开播；未开播则等待后续 RSS 周期重试，已开播则继续匹配 TMDB。
4. 同时生成完整标题、“基础标题 + 季号”和明确分隔的“主剧名 + 篇章名”候选；篇章候选会读取 TMDB 全部分季名称确定真实季度。
5. 创建前同时检查活动订阅与电视剧订阅历史；相同 `tmdb_id + season` 已存在时跳过并写入永久成功索引。
6. 豆瓣已有明确总集数时按该集数创建；已经开播但总集数未知时暂按 100 集创建。两种情况都设置 `manual_total_episode=1`。
7. 创建后重新读取数据库，确认集数和锁定标记均已保存。
8. 临时 100 集订阅会在每个插件执行周期复核豆瓣；取得明确总集数后立即回写，并按已完成进度重新计算缺失集数。
9. 受管订阅完成后否决 MoviePilot 的首次自动删除，将卡片改为暂停并等待设定的确认天数。
10. 到期后只读取一次豆瓣详情，比较最新总集数与订阅完成时的总集数。
11. 豆瓣总集数没有增加时，调用 MoviePilot 自身的完成入口，写入订阅历史并删除卡片；增加时更新总集数和缺失集数，恢复订阅并立即搜索新增集。
12. 每天 08:00 检查 MoviePilot 中全部活动电视剧订阅，通过 TMDB 记录当天有排期的订阅及当前完成进度。
13. 到订阅补齐周期时再次读取当天快照中的订阅；进度增加则跳过，进度不变则调用 MoviePilot 卡片菜单同款搜索，多个订阅之间间隔 2 分钟。

锁定使用 MoviePilot 自身的“手动修改过总集数”字段。MoviePilot 后续刷新元数据时会保留该总集数，不会用 TMDB 集数覆盖。要求 MoviePilot `2.15.0` 或更高版本。

## 配置

- `RSS 地址`：每行一个 `http` 或 `https` 地址，默认示例为 `http://192.168.110.31:9150/rsshub/hot_tv`。
- `执行周期`：五段 Cron，默认每 6 小时执行一次。
- `订阅补齐执行周期`：五段 Cron，默认每天 23:00 执行。每日进度快照固定在 08:00，因此该周期应设置在 08:00 之后。
- `每个 RSS 最大条目数`：单次从每个地址处理的上限，默认 50。
- `确认完成天数`：订阅完成并暂停后，等待多少天复核豆瓣总集数，默认 7 天。
- `需要订阅的剧集类型`：可多选国产剧、欧美剧、日韩剧和其他地区，默认全部。
- `RSS 使用代理`：仅影响 RSS 请求；内网 RSS 地址通常不要开启。

数据页面可按关键词、结果分组和地区分页搜索全部记录，失败条目支持单条重试；每条 TMDB 查询路径会记录搜索词、模式、结果数、详情数、请求次数和错误。完整历史不按条数截断，成功创建、活动订阅已存在或订阅历史已存在的 RSS 条目另有永久去重索引，所以即使卡片已完成删除也不会重复订阅。

“今日订阅补齐”页面展示 TMDB 当日排期、08:00 进度、晚间进度和搜索状态。补齐任务只读取当天快照，不会把今日未找到的剧集累积到明日；同一天完成后再次触发也不会重复搜索。若当天 08:00 没有生成快照，或只存在旧日期快照，晚间任务会直接跳过。

## 安全边界

- 不使用 TMDB 集数代替豆瓣总集数。
- 豆瓣总集数缺失时，只有豆瓣明确显示已开播且 TMDB 匹配达到固定可信线才会暂按 100 集创建；待播条目不会创建。
- 仅接管本插件以“豆瓣订阅助手”用户创建的订阅；相同 `tmdb_id + season` 的用户原订阅不会被修改。
- 每日补齐是独立的只读检查，覆盖所有用户创建的活动电视剧订阅；它只触发 MoviePilot 原生搜索，不修改这些订阅的总集数、缺失集数或锁定状态。
- 普通完成确认阶段若豆瓣详情暂时无法取得明确总集数，会保持暂停卡片并在 1 天后重试；临时 100 集订阅则按插件的每个执行周期复核。

详细匹配算法与风险分析见仓库根目录的 `豆瓣接口与TMDB电视剧匹配设计.md`。
